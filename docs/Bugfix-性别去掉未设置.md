# Bugfix 设计：性别选项去掉「未设置」

> 状态：v1.0，待评审后由 eng-coder 实施

## 问题
「我的 → 编辑档案」性别选择有三个按钮：`未设置 / 👦男宝 / 👧女宝`。用户要求**去掉「未设置」**，只留男宝/女宝，避免宝宝性别留空。

## 现状
`js/views/profile.js` 的 `openProfileEditor()` 中：
```js
const genderBtns = [['', '未设置'], ['male', '👦 男宝'], ['female', '👧 女宝']]...
```
第一个元素 `['','未设置']` 即"未设置"按钮。

## 影响
- 仅影响档案编辑弹窗的性别按钮展示。
- 数据层 `gender` 仍可安全为 ''（旧有未设置的宝宝档案）——读取时 `genderLabel('')` 已返回「未设置」，展示不影响；保存时若用户未点性别，`f.gender` 仍可能为 ''，这与现状容错一致（null/空 gender 允许）。
- 档案"完善度"横条判断 `!baby.gender` 逻辑不变——若宝宝无性别仍会提示补全，符合预期。

## 修复方案（仅改 js/views/profile.js 一处）
将第 167 行 `genderBtns` 数组改为仅两项：
```js
const genderBtns = [['male', '👦 男宝'], ['female', '👧 女宝']].map(...)
```

## 显式不做
- 不改数据模型、"完善度"判断逻辑、其他按钮。
- **不强制作选性别**：去掉「未设置」按钮仅移除该选项；无性别宝宝保存后仍可为 ''（现状容错）。若日后需"必须选性别"再单独设计。
- 不改其他文件。

## 验收标准
1. 编辑档案弹窗性别仅显示「男宝」「女宝」两个按钮，无「未设置」。
2. 仍可选中其一（默认选中当前档案的性别；若无性别则都不选中）。
3. 保存后性别正常写入并显示。
4. 已有无性别宝宝档案仍可正常展示与编辑。
